# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Agent Box: a Python 3 package (stdlib only) that runs AI coding agents (Claude Code, opencode, codex) inside an unprivileged sandbox — **bubblewrap (`bwrap`)** on Linux, **podman** elsewhere (e.g. macOS, where bwrap can't run). Both sandboxes share one toolchain, one set of bind tables, and one install script; only the sandbox wrapper differs. The implementation lives in `agtbox/`; `bin/agtbox.py` is a thin shim that adds the repo root to `sys.path` and calls `agtbox.cli.main()`. `test/` is the `unittest` suite (stub-sandbox integration tests + unit tests of the pure helpers). (Human-facing setup/usage live in `README.md`; this file is the terse architecture reference.)

## Common commands

```bash
./bin/agtbox.py [-a DIR] [-w VOL] [-r VOL] [-s bwrap|podman] [-b] [-u] claude|opencode|codex|bash [-- agent args...]
```

- Flags (`-a`/`-w`/`-r`/`-s`/`-b`/`-u`, plus argparse's `-h`) come **before** the agent name; the agent's own args go **after a `--` separator** and are passed **verbatim** (no flag remapping) — session handling is each agent's own syntax (claude `--continue`/`--resume [ID]`/`--fork-session`; opencode `--continue`/`--session ID`/`--fork`; codex `resume [ID]`/`fork [ID]`). A bare `agtbox.py <agent>` needs no `--`. `-w` = read-write bind, `-r` = read-only bind, both at the same host path. `-s` forces a sandbox (default: auto — highest priority available); `-b` rebuilds the sandbox image (no-op for sandboxes without one); `-u` refreshes the toolchain and the agent's packages before running (replaces `AGTBOX_REINSTALL=1`, which is gone).
- The toolchain auto-installs into `~/.local/share/agent-box` on first run. Test suite: `python3 -m unittest discover -s test` (or `python3 -m agtbox`).

## Architecture

**A sandbox over a per-user toolchain, two sandboxes.** node, `uv`, the three agent CLIs, and `gh`/`glab` (GitHub/GitLab CLIs) live in `~/.local/share/agent-box` (bind-mounted, the *same* toolchain for both sandboxes). Under **bwrap** (Linux) the rest comes from the host's `/usr` (python, git, ripgrep, compilers, …); under **podman** it comes from the image (`container/Containerfile`, `debian:trixie` + git/ripgrep/openssh-client/build-essential/…), since the host may be macOS. `discover_sandboxes()` finds sandbox plugins in `agtbox/sandboxes/`; `resolve_sandbox()` picks the highest-priority available one (or validates an explicit `-s` choice). Requires `bwrap` + unprivileged user namespaces (validated on Debian 13 / aarch64), or podman (verified on rootless podman 5.4.2 / Debian / aarch64; macOS still to confirm).

**Launcher — `bin/agtbox.py` shim + `agtbox/` package.** `bin/agtbox.py` is a ~10-line shim: it prepends the repo root to `sys.path` and calls `agtbox.cli.main()`. The package is also runnable as `python3 -m agtbox`. `cli.main()` splits argv on the first `--` (everything after it is the agent's argv, verbatim), then parses the left side with **argparse** (`-a/-w/-r/-s/-b/-u` + an `agent` `choices` positional built from discovered agent names). argparse owns help/validation: `-h` → stdout/exit 0, a bad flag/agent/sandbox → stderr/exit 2 (standard conventions; no hand-rolled `usage()`). Agents and sandboxes are **discovered at runtime** from `agtbox/agents/` and `agtbox/sandboxes/` via `pkgutil.iter_modules` — adding a file automatically makes the new agent or sandbox visible in `--help` and to the arg validator. `discover_agents()` / `discover_sandboxes()` import each non-`base` module and collect all subclasses of `Agent` / `Sandbox`. The `cli.main()` orchestration: discover → parse → `resolve_sandbox` → instantiate agent → `normalize_paths` → assemble binds/env → build `RunContext` → optionally `sandbox.rebuild()` → `sandbox.prepare()` → `ensure_tools()` → `sandbox.run()`.

**The bwrap sandbox (`agtbox/sandboxes/bwrap.py`).** Locked-down: hard `--ro-bind /usr` + `/etc` (essential — fail loudly if absent), plus `--ro-bind-try /bin /sbin /lib /lib64 /opt /cpe` read-only (each skipped if missing — robust across merged-`/usr`/minimal Linux; `/lib64` is absent on aarch64, `/opt` may be absent, `/cpe` is an HPC-host path absent on most machines). **DNS fix:** `/etc/resolv.conf` is commonly a symlink into `/run` (systemd-resolved, SLES netconfig), and `/run` isn't in the sandbox, so the link dangles and every lookup fails with "Could not resolve host". After the `/etc` bind, `--ro-bind-try $(realpath /etc/resolv.conf) $(realpath …)` recreates the resolved file at *its own real path* (e.g. `/run/netconfig/resolv.conf`) so the symlink already inside the bound `/etc` resolves. NB bind at the realpath, **not** onto `/etc/resolv.conf` — binding onto the symlink makes bwrap follow it to the missing `/run` target and die with "Can't create file at /etc/resolv.conf: No such file or directory". A real-file resolv.conf realpaths to itself → harmless rebind; podman needs none — it builds its own. **TLS trust-store fix (same trap):** on SLES/openSUSE the CA bundle lives in `/var/lib/ca-certificates` and `/etc/ssl/{certs,ca-bundle.pem}` are symlinks into it, so without `/var` the sandbox has **no CAs** and every HTTPS fetch fails "unable to get local issuer certificate" — `--ro-bind-try /var/lib/ca-certificates /var/lib/ca-certificates` makes those `/etc/ssl` symlinks resolve (skipped on distros that keep certs under `/etc`/`/usr`, already bound; this is the host's own trust store, so any corporate CA the host already trusts comes along). Then `--dev /dev --proc /proc --tmpfs /tmp`; `--tmpfs "${HOME}"` (empty ephemeral home); read-write `--bind` for the three persistent dirs (`~/.local/share/agent-box`, `~/.cache/agent-box`) + the project (`APP_DIR`, same path) + the per-agent config binds; `--die-with-parent --unshare-pid/ipc/uts`. Network is **shared** (no `--unshare-net` — agents need their APIs). A standalone `--` ends bwrap's option parsing so a `-`-leading agent arg can't be misread. Built as an argv list and exec'd directly — never assembled into a shell string.

**The podman sandbox (`agtbox/sandboxes/podman.py`).** For hosts without bwrap (macOS). The image (`container/Containerfile`, `debian:trixie` + the runtime/build packages; node/uv/CLIs are NOT baked in — they come from the bound toolchain) is the read-only rootfs, so there are **no system-dir binds** — the podman sandbox mirrors bwrap by mounting everything at the **same host path** and setting `HOME=${HOME}`, so the bind tables, `AGENT_BIN`, and `PATH` are reused verbatim (`--bind a b`→`-v a:b`, `--ro-bind a b`→`-v a:b:ro`, `--setenv K V`→`-e K=V`). It runs as the container's root, which rootless podman maps to the invoking host user, so the agent's writes are owned by you AND `$HOME` is writable — **no `--userns=keep-id`** (that maps you to uid 1000 inside, which leaves `$HOME`'s auto-created mount parents root-owned/unwritable and breaks opencode's postinstall). `--security-opt label=disable` (SELinux hosts; avoids relabeling the shared dirs with `:z`/`:Z`). Network shared (no `--network`). `rebuild()` lazily builds on first podman run (or `-b`); it calls `refresh_certs` to copy the host's company CA certs (`~/.local/share/certs/*`, or `$AGENT_CERTS_DIR`; missing/empty is fine) into `container/certs/` (gitignored bar a `.gitkeep`), which the Containerfile `COPY`s + `update-ca-certificates`'s into the image trust store — needed behind a TLS-intercepting proxy whose CA isn't in fresh-Debian's store. Certs must be PEM with a `.crt` extension. bwrap needs no cert logic: its `--ro-bind /etc` already exposes the host trust store. `derive_tz` (podman only) passes the host zone as `TZ` — bwrap inherits host time via its `/etc` bind, but a fresh container is UTC; setting `TZ` is portable to macOS where binding `/etc/localtime` would dangle. **macOS caveat:** podman runs a Linux VM that shares `$HOME`, so the agent-box dirs and the project must live under `$HOME`. Verified end-to-end on rootless podman (Debian/aarch64): image build + in-container toolchain install + all three agents launch, files owned by the host user; macOS itself still to confirm.

**Four writable persistent dirs (everything else is read-only or ephemeral tmpfs).** Each XDG base has an `agent-box/<agent>` namespace bound onto the agent's real path.
- `~/.local/share/agent-box/<arch>` (`AGENT_TOOLS`, `<arch>` = `os.uname().machine`): node + npm + `uv` + the agent CLIs + `gh`/`glab` + **all global installs** the agents make (`npm -g`, `pip`, `uv tool` — anything not in a venv) + per-agent **data** (opencode's `~/.local/share`). Bound rw, persists across runs, shared between agents, so installs stick and CLIs auto-update. **Namespaced by CPU arch** so one shared filesystem can serve nodes of different architectures (e.g. an HPC cluster whose x86_64 + aarch64 nodes mount the same `$HOME`): the toolchain is arch-specific native binaries and pip/uv/npm install for the current platform into one flat prefix without arch-namespacing, so a single shared tree would hand the wrong-arch binary to the other node (Exec format error) — and, because the `.stamp` marker would already be present, `ensure_tools` wouldn't even self-correct. Each arch gets its own toolchain + `.stamp` here; the other three dirs below stay un-namespaced (arch-independent → logins/state/caches shared across arches). Env routes installs here (`npm_config_prefix`, `PIP_PREFIX`/`PYTHONUSERBASE` + `PIP_BREAK_SYSTEM_PACKAGES=1`, `UV_TOOL_DIR`/`UV_TOOL_BIN_DIR`) and caches to `~/.cache/agent-box` (`npm_config_cache`, `PIP_CACHE_DIR`, `UV_CACHE_DIR`). `PATH` = `${AGENT_TOOLS}/bin:${AGENT_TOOLS}/node/bin:/usr/bin:/bin`.
- `~/.config/agent-box` (`AGENT_CONFIG`): per-agent **config**, wired in by each agent's `binds` property — each entry is a full `host-source:sandbox-path` `Bind` pair bound straight onto the agent's expected path (`~/.claude`, `~/.codex`, opencode's config, `~/.config/{git,gh,glab-cli}` for git + the git-hosting CLIs, and `~/.ssh` for keys/`known_hosts` so the agents can push over SSH). Because the source is a full path, each XDG category binds from the matching base: opencode's config from `${AGENT_CONFIG}`, data from `${AGENT_TOOLS}`, state from `${AGENT_STATE}`, cache from `${AGENT_CACHE}` (each `agent-box/opencode` → the real `~/.config`,`~/.local/share`,`~/.local/state`,`~/.cache` path). `~/.claude.json` is a **file bind** (seeded `{}` if absent — must be valid JSON). **git is the exception:** a *file* bind of `~/.gitconfig` can't be rewritten (git writes via temp+rename → `EBUSY` on the mountpoint), so git binds the `~/.config/git` **dir** with an empty seeded `config` and writes there natively — no `GIT_CONFIG_GLOBAL`. `~/.ssh` is a dir bind for the same reason (`ssh-keygen -R` rewrites `known_hosts` via temp+rename); `ensure_sources` `chmod 700`s the source so ssh accepts it (private keys still need `0600`).
- `~/.local/state/agent-box` (`AGENT_STATE`): per-agent **state** (opencode's `~/.local/state`).
- `~/.cache/agent-box` (`AGENT_CACHE`): npm/pip/uv download **caches** + per-agent cache (opencode's `~/.cache`).

**Env union.** `ENV_FORWARD` (`ANTHROPIC_*`/`OPENAI_API_KEY`/`CODEX_API_KEY`/`OPENCODE_ENABLE_EXA`) forwarded when set (from each agent's `env_forward`); `ENV_LITERAL` (`CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS=1` + `OPENCODE_EXPERIMENTAL_LSP_TOOL=true`, plus `TZ` under podman) always (from `env_literal`). opencode's Exa web search is **off by default** — it's forwarded, not always-on, so it turns on only if you `export OPENCODE_ENABLE_EXA=1`. Emitted as `--setenv NAME VALUE` (bwrap) or `-e NAME=VALUE` (podman). Agent-independent — an agent ignores env it doesn't read.

**Auto-install on first run (`ensure_tools`).** If the `${AGENT_TOOLS}/.stamp` completion marker (written only after a fully successful install) or the requested agent binary is missing (or `-u`/`--update` is passed), install runs in an isolated context inside the sandbox — bwrap (toolchain + cache rw, system ro, `$HOME` tmpfs) or podman (`podman run` with toolchain + cache rw; the container *is* the isolation) — so the official installers can't touch the host. The shared `install_script` (in `agtbox/install.py`) resolves the **current LTS** node from `nodejs.org/dist/index.json` and downloads the tarball into `${AGENT_TOOLS}/node` — no pinned version, so an update tracks upstream's latest LTS — then installs `uv`, `gh`/`glab` (their latest release tarballs, arch-matched), and the agent's `packages` via `npm install -g`. **node + the npm CLIs are required (fail hard); `uv`/`gh`/`glab` are auxiliary and best-effort** — each wrapped in `|| { warn; skipped+=… }`, so on a locked-down network where `astral.sh`/`github.com`/`gitlab.com` are blocked (but the node/npm registries aren't) the install warns, skips, and still writes `.stamp` (so the core toolchain completes and isn't re-downloaded every run; `-u` retries the skipped ones). The script always targets **linux** (the toolchain only ever runs inside Linux); the **arch** comes from the host's `uname -m` under bwrap but from the *container's* `uname -m` under podman (a macOS host is a different OS/arch). Reads inputs from `AGT_*` env vars. Idempotent (re-run upgrades).

**Adding an agent.** Drop a file in `agtbox/agents/` that defines a class subclassing `Agent` (from `agtbox.agents.base`). Set `name` (the CLI name and the argparse choice), `packages` (npm package list to install), `binds` (list of `Bind` objects for agent-specific config paths), `env_forward` (env vars to forward from host when set), and `env_literal` (env vars always set). Discovery is automatic — no changes to argparse choices or install tables needed. See `agtbox/agents/claude.py` or `agtbox/agents/opencode.py` for examples.

**Pointing agents at local models.** The launcher forwards the env union when set: claude reads `ANTHROPIC_BASE_URL`/`ANTHROPIC_AUTH_TOKEN`/`ANTHROPIC_DEFAULT_SONNET_MODEL` (e.g. LM Studio). codex ignores `OPENAI_BASE_URL`, so its local endpoint goes in `~/.config/agent-box/codex/config.toml`.

**Isolation model.** The agent can persist only to the project + the four `agent-box` dirs. Under **bwrap**, real `$HOME` is an empty tmpfs and `/` is read-only, so it can't read the user's dotfiles/keys or write elsewhere; env is wiped (`--clearenv`) and re-built from the allowlist, so host secrets in the shell env don't leak. Under **podman** the rootfs is the image (the host FS isn't visible at all except the explicit binds), and env starts empty (only `-e` reaches it) — equivalent isolation, different mechanism. Global installs persist + are shared across runs by design. Two residual exposures are inherent/host-side, not launcher bugs: network is **shared** (so host `127.0.0.1` services are reachable — agents need outbound for their APIs), and TTY injection via the legacy `TIOCSTI` ioctl is a host concern (recommend `dev.tty.legacy_tiocsti=0`; `--new-session` would close it but breaks the interactive TUIs).
