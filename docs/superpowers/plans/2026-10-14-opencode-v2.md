# opencode 2.0 (standalone) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `agtbox.py opencode` installs and runs opencode 2.0 (`@opencode/cli`) in `--standalone` mode, with v2's shared background service disabled on every launch.

**Architecture:** Three new `Agent` class attributes carry the opencode-specific behavior so the sandboxes stay generic: `obsolete_packages` (npm-uninstalled before the install), `default_args` (prepended to the user's args at launch), `setup_args` (a one-shot command run in the normal agent sandbox before every launch). The sandboxes gain a shared `command(ctx)` helper and an optional `cmd` override on `build_run_argv`, which `run_setup` uses.

**Tech Stack:** Python 3 stdlib, `unittest`, bash install script, bwrap/podman.

Spec: `docs/superpowers/specs/2026-10-14-opencode-v2-design.md`.

## Global Constraints

- stdlib only; no new dependencies.
- Sequence class defaults on `Agent` are **tuples** (`()`), never lists.
- User args after `--` stay verbatim and come **after** `default_args`.
- Argv is a list passed to `exec`/`subprocess` — never a shell string.
- No automatic v1→v2 upgrade trigger: the user runs `agtbox.py -u opencode`.
- A failing setup command **warns and continues** (doesn't block the launch): until `-u`, the toolchain still has v1, which doesn't know `service set`.
- Test command: `python3 -m unittest discover -s test` (run from repo root).
- Default to no code comments; one short line only where the WHY is non-obvious.
